Organizar conhecimento.

Um sistema de biblioteca para organizar livros, autores, editoras, leitores, exemplares e empréstimos de forma consistente.

Conheça o projeto

01 • Contextualização

O problema que queremos resolver

Uma biblioteca que controla seus registros em cadernos ou planilhas separadas pode enfrentar dados duplicados, dificuldade para localizar exemplares, erros no acompanhamento de empréstimos e demora para produzir relatórios.

🗂️

Informações organizadas

Livros, autores, categorias e editoras possuem registros próprios e relacionados por identificadores.

🔎

Pesquisas mais rápidas

Consultas SQL ajudam a encontrar títulos, verificar disponibilidade e acompanhar empréstimos.

🔐

Integridade dos dados

Chaves primárias, estrangeiras e restrições reduzem referências inválidas e duplicidades.

02 • Modelo lógico

Como os dados se conectam

O banco foi dividido em tabelas que representam os elementos principais da biblioteca. As tabelas associativas permitem relacionamentos muitos-para-muitos.

editorasUma editora pode publicar vários livros (1:N).
livrosUm livro pode ter vários exemplares (1:N).
autores ↔ livrosRelacionamento N:N por meio de livros_autores.
categorias ↔ livrosRelacionamento N:N por meio de livros_categorias.
leitores → empréstimosUm leitor pode realizar vários empréstimos (1:N).
exemplares → empréstimosUm exemplar pode aparecer em diferentes empréstimos ao longo do tempo (1:N).

O diagrama lógico do projeto deve ser incluído no repositório junto dos demais materiais.

03 • Fundamentação teórica

Formas normais

A normalização organiza as tabelas para diminuir redundâncias e evitar anomalias de inserção, atualização e exclusão.

1FN

Valores atômicos

Cada campo guarda um único valor, sem listas de dados na mesma célula.

2FN

Dependência completa

Todo atributo não-chave depende da chave primária completa, não apenas de parte dela.

3FN

Sem dependência transitiva

Atributos não-chave não devem depender de outros atributos não-chave.

4FN

Dependências multivaloradas

Relações multivaloradas independentes devem ser separadas para evitar combinações redundantes.

04 • SQL na prática

Exemplos de consultas

As consultas do projeto demonstram junções, filtros, agrupamentos, ordenação e funções de agregação.

INNER JOIN
SELECT l.titulo, e.nome AS editora
FROM livros l
INNER JOIN editoras e ON e.id_editora = l.id_editora;

Exibe cada livro junto do nome da editora responsável.

WHERE + LIKE
SELECT titulo
FROM livros
WHERE titulo LIKE '%estrela%';

Busca títulos que contenham a palavra “estrela”.

GROUP BY + COUNT
SELECT estado, COUNT(*) AS quantidade
FROM exemplares
GROUP BY estado
ORDER BY quantidade DESC;

Conta quantos exemplares existem em cada estado de conservação.

O arquivo sql/03_consultas.sql contém o conjunto completo de consultas do trabalho.
